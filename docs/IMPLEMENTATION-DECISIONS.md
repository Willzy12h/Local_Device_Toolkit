# Implementation decisions

These decisions map the accepted plan to the implemented structure. Native acceptance is recorded separately.

- The user selected a new WPF toolkit from the relevant M365 source. All 30 original Windows controls remain intact in reference JSON; local checks and actions have separate, explicit coverage. Source branch, commit and hashes are retained in `provenance/import-manifest.json`. The unavailable WinForms toolkit was not recovered or represented as imported.
- One workflow/task catalogue and `WorkbenchSession` serve setup and diagnostics. WPF code handles presentation/dialogs; typed engine services own planning, evidence and execution. This replaces the proposed separate view-model class per page without duplicating operations or scripts.
- Closed typed settings adapters replace one class per DWORD. Exact registry absence, active power scheme and battery sleep values are evidence. Time-zone privilege is inspected independently of machine scope. Original-user operations never switch to an alternate administrator profile.
- Fixed script DTOs and embedded reviewed pins replace a generic script input binder. Only three fixed scripts are registered: device facts, original-user preferences/Copilot, and original-user MSIX. They retain ordinary PowerShell execution policy. There is no arbitrary elevated script/command form.
- Plans retain full before observations, expire after ten minutes and fit the bounded pipe frame. Logical targets are shared across fixed-setting changes and restoration. Identical requests deduplicate; conflicting requests require explicit removal/replacement. Profile/media disappearance cannot prevent removing an existing queue row.
- Restoration accepts original source IDs plus an expected setting type. The type is only a claim: execution independently resolves and verifies original evidence. Machine targets come from administrator-controlled journals, not a user preview. Original registry absence can be restored; drift blocks restoration. Installers, Copilot removal and regional language changes have no generic undo.
- Profiles are immutable and content-addressed. Administrator approval only approves a configuration; installation is separate. User copies supply selection/preview. The machine worker loads its own protected copy; original-user MSIX independently reads protected, administrator-writable/readable-to-users profile configuration. Journals, staging and runtime storage retain their separate access restrictions.
- MSI, per-machine OneDrive, current-user MSIX/bundles and local Office ODT use closed adapter arguments. Office product selection and licensing/EULA authorization are explicit inputs, not fabricated licenses. Complete media hashes, Windows trust, signer pins, metadata and dependency checks precede execution. Missing client/vendor inputs remain manual.
- Installer supervision never kills or automatically retries a mutation. A persistent product guard survives interruption; PID/start identity is saved immediately. Known completion releases the guard only after durable results. Explicit completion review requires fresh installed identity and an absent original process, or positive evidence of a different native boot identifier when process identity was lost. It never rewrites an uncertain original run.
- Reports load selected immutable records and preserve complete captures, source times, original requester and actual actor. Manual reviews cannot complete missing, malformed or failing automatic checks. Historical evidence stays dated; a completion receipt is separate evidence. HTML/CSV/JSON exports are non-overwriting by default.
- Portable tests and native CI are distinct. Native rendering uses actual Windows identity and real views without sample device facts or configuration writes. Compact renders are layout checks, not physical DPI, keyboard or Narrator acceptance. Real settings, UAC credentials and vendor installations remain explicit Windows acceptance gates.
