# Select, review and run

The user approved setup concept A (task table), diagnostics concept C (list/details), atomic selections and concise text. Their execution brief adds a seamless select → inspect/review → confirm/apply/verify flow with one new dated log per run. This is authorization to implement the existing workflows directly.

- Each meaningful change has its own checkbox. UK formats, home country, input language, keyboard and default keyboard are distinct operations. Checks never automatically apply fixes; no group select-all or hidden prerequisite selection.
- Setup shows selection, task, current value, expected value, status and account. Diagnostics retains selectable checks with one task's results/details. Both use the same registered tasks and queue; selection persists across filters/navigation and invalidates pending review when changed.
- Before confirmation, inspect every selected item, present friendly current/expected values, exact source/registry location, and explicit missing/different/already-correct/unreadable/blocked states. Unknown values are never treated as missing. Already-correct items are skipped, not rewritten. Blocked items never become runnable without a fresh valid review. Existing ten-minute expiry and dispatch-time reread/drift checks remain.
- A new current-user log is created with UTC date/time and a unique run identifier when selected work is checked. Append selection, checks, exact source and values, review/confirmation/cancellation, start/result, actual actor and independently verified after-state to the same file. No truncation/overwrite or installer replay. Display the path and live dated output. A new selection/review run creates a new file. The text log is a companion to immutable and protected evidence, never an authorization source.
- Persist pre-change logging before dispatch; failure blocks new actions. If logging fails after dispatch, preserve the uncertain result and stop remaining actions. Never claim a successful write/readback when unavailable.
- Keep administrator review, original-user targeting, protected journals and registered-operation boundaries. No generic registry path editor, arbitrary command runner, execution-policy bypass or client installer defaults.
- Native Windows CI must exercise actual table/diagnostic layouts, compact reachability, keyboard-selectable row controls, review grid and log view. Real-device mutations/UAC/vendor/accessibility acceptance remain explicit manual gates.
